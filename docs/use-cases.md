# Use Cases — LegalMate

Actors: **Lawyer**, **Client**, **Admin**

| Use Case | Actors | Relations |
|---|---|---|
| Register | Lawyer, Client | — |
| Login | Lawyer, Client | «include» verify password, «extend» display login error |
| Posting | Lawyer, Client | «extend» create post, create comment |
| Reading | Lawyer, Client | «extend» Search / Bookmark / Download e-book |
| Lawyer_request | Client, Admin | «extend» Chat |
| Chat | Lawyer | extends Lawyer_request |

---

## UC-01: Register

| Item | Description |
|---|---|
| Actor | Client, Lawyer |
| Precondition | ผู้ใช้ยังไม่มีบัญชี |
| Main flow | 1. ผู้ใช้กด "Sign Up" จากหน้า Login<br>2. เลือกบทบาท **Client** หรือ **Lawyer**<br>3. กรอก ID/Passport, First Name, Last Name, Email, Password, Confirm Password, Phone, Date of Birth<br>4. กด "Sign Up"<br>5. ระบบตรวจสอบข้อมูลและสร้างบัญชี<br>6. ระบบกลับไปหน้า Login พร้อมกรอก Email ไว้ให้ |
| Alternative flow | 5a. ข้อมูลจำเป็นไม่ครบ / Email ผิดรูปแบบ / รหัสผ่านสั้นกว่า 6 ตัว / รหัสผ่านไม่ตรงกัน / วันเกิดผิดรูปแบบ → แสดงข้อความผิดพลาด<br>5b. Email ซ้ำในระบบ → แสดงข้อความผิดพลาด (เมื่อมี backend) |
| Postcondition | มีบัญชีผู้ใช้ใหม่พร้อม role |
| UI | `docs/figma` — Sign Up |

## UC-02: Login

| Item | Description |
|---|---|
| Actor | Client, Lawyer |
| Precondition | ผู้ใช้มีบัญชีแล้ว |
| Main flow | 1. ผู้ใช้กรอก Email และ Password<br>2. กด "Login"<br>3. ระบบ **verify password** («include»)<br>4. ระบบพาเข้าสู่หน้าหลัก (Bottom Tabs: Community, E-Book, Chat, Profile) |
| Alternative flow | 3a. **display login error** («extend»): ช่องว่าง, Email ผิดรูปแบบ, หรือ Email/Password ไม่ถูกต้อง → แสดงข้อความผิดพลาดใต้ช่องกรอก |
| Postcondition | ผู้ใช้อยู่ในสถานะล็อกอิน (`isLoggedIn = true`) |
| UI | `docs/figma` — Login |

## UC-03: Posting

| Item | Description |
|---|---|
| Actor | Client, Lawyer |
| Precondition | ผู้ใช้ล็อกอินแล้ว |
| Main flow | 1. ผู้ใช้เปิดแท็บ Community ระบบแสดงรายการโพสต์ล่าสุด (ชื่อผู้โพสต์, หัวข้อ, เนื้อหาย่อ, รูปสูงสุด 3 รูป + "+N more", จำนวนคอมเมนต์)<br>2. ผู้ใช้ค้นหาโพสต์ด้วยคำค้น (ไม่บังคับ)<br>3. ผู้ใช้แตะโพสต์เพื่อดูรายละเอียดและคอมเมนต์ทั้งหมด |
| Extension: create post | **เฉพาะ Client** — ทนาย (Lawyer) สร้างโพสต์ไม่ได้ ทำได้แค่คอมเมนต์ (ไม่เห็นปุ่ม + และ backend ตอบ 403)<br>1. กดปุ่ม + → กรอกหัวข้อและรายละเอียด แนบรูปได้สูงสุด 5 รูป (ลบรูปที่เลือกได้) เลือกได้ว่าจะโพสต์แบบไม่ระบุตัวตน<br>2. กด "โพสต์" → กลับหน้า Community และเห็นโพสต์ใหม่บนสุด<br>1a. หัวข้อหรือรายละเอียดว่าง → แสดงข้อความผิดพลาด<br>1b. ไฟล์ไม่ใช่รูป / เกิน 5 MB / เกิน 5 รูป → แสดงข้อความผิดพลาด |
| Extension: create comment | 1. ในหน้ารายละเอียด พิมพ์ความคิดเห็นแล้วกดไอคอนดินสอ<br>2. กด "reply" ใต้คอมเมนต์เพื่อตอบกลับ → คำตอบแสดงเยื้องใต้คอมเมนต์นั้น พร้อมระบุว่าตอบกลับใคร<br>คอมเมนต์ของทนายแสดงป้าย "ทนาย" |
| Alternative flow | แตะรูปในหน้ารายละเอียดเพื่อดูเต็มจอ ปัดเปลี่ยนรูปได้<br>เจ้าของโพสต์ลบโพสต์ได้ (ไอคอนถังขยะ + ยืนยัน) คอมเมนต์และไฟล์รูปถูกลบด้วย<br>เจ้าของคอมเมนต์ลบคอมเมนต์ได้ (ปุ่ม "ลบ" + ยืนยัน) คำตอบใต้คอมเมนต์ถูกลบด้วย |
| Business rules | โพสต์ไม่ระบุตัวตน: backend ไม่ส่งข้อมูลผู้เขียนให้ผู้อื่นเลย · หัวข้อ ≤ 150 ตัว, รายละเอียด ≤ 5,000 ตัว, คอมเมนต์ ≤ 2,000 ตัว |
| Postcondition | โพสต์/คอมเมนต์ถูกบันทึกในฐานข้อมูล |
| UI | `docs/figma` — posting, comment |

## UC-04: Reading

| Item | Description |
|---|---|
| Actor | Client, Lawyer (ทุก role ใช้ได้เหมือนกัน) — การเพิ่มหนังสือเป็นหน้าที่ของ Admin (ทำภายหลัง) |
| Precondition | ผู้ใช้ล็อกอินแล้ว |
| Main flow | 1. ผู้ใช้เปิดแท็บ E-Book ระบบแสดงหนังสือแยกตามหมวด (อาญา / แพ่งและพาณิชย์ / มหาชน) เลื่อนดูแนวนอนได้<br>2. กดลูกศร › ท้ายหมวดเพื่อดูหนังสือทั้งหมดในหมวด<br>3. แตะหนังสือ → หน้า E-Book Details (ผู้จัดทำ, ฉบับปรับปรุงถึง, ปีที่ประกาศใช้, จำนวนหน้า, แหล่งที่มา)<br>4. กด "อ่าน" → อ่าน PDF ในแอป พร้อมตัวบอกหน้า |
| Extension: Search e-book | กดช่อง Search → พิมพ์คำค้น ระบบค้นจากชื่อและคำอธิบาย (ไม่พิมพ์ = แสดงทั้งหมด) · ไม่พบ → แสดงข้อความ · กด "ยกเลิก" เพื่อกลับ |
| Extension: Bookmark e-book | กดหัวใจในหน้ารายละเอียดเพื่อเพิ่ม/เอาออกจาก Favorite · ดูรายการได้จากไอคอนหัวใจมุมซ้ายบนของหน้า E-Book |
| Extension: Download e-book | กด "Download PDF" → มือถือ: บันทึกไฟล์ในเครื่องแล้วเปิดเมนูแชร์ (บันทึกลง Files / เปิดด้วยแอปอื่น) ครั้งต่อไปปุ่มเปลี่ยนเป็น "เปิด/แชร์ PDF" · เว็บ: เปิดไฟล์ในแท็บใหม่ |
| Business rules | หนังสือเป็นตัวบทกฎหมายจริงจากเว็บไซต์หน่วยงานรัฐ พร้อมระบุฉบับและแหล่งที่มา · ปกหนังสือแอปวาดเอง (ไม่ใช้ปกหนังสือที่มีลิขสิทธิ์) |
| Postcondition | สถานะ Favorite ถูกบันทึกในฐานข้อมูล / ไฟล์ PDF ถูกบันทึกในเครื่อง |
| UI | `docs/figma` — reading, reading_download, reading_search, reading_favorite |

## UC-05: Lawyer_request

| Item | Description |
|---|---|
| Actor | Client (ส่งคำขอ), Admin (พิจารณา), Lawyer (ได้รับมอบหมาย) |
| Precondition | ผู้ใช้ล็อกอินแล้ว |
| Main flow (Client) | 1. แท็บ Chat → การ์ด "Request legal assistance" → กด Request<br>2. หน้ารายการคำขอ (สถานะ: รอตรวจสอบ / อนุมัติแล้ว / ปฏิเสธ) → กด New Request<br>3. ฟอร์ม "Consult with Us": หัวข้อ, ลำดับเหตุการณ์ (บังคับ), ข้อความถึงทีมงาน (ไม่บังคับ) → Send<br>4. หน้า **Awaiting Review** — แอปเช็กสถานะใหม่ทุก 10 วินาที<br>5. เมื่ออนุมัติ → เครื่องหมายถูก + ชื่อทนาย + ปุ่ม **Ready to Chat** และทนายจะแสดงในรายการ "แชทกับทนาย" |
| Main flow (Admin) | 1. แท็บ "คำขอปรึกษา" กรองตามสถานะ<br>2. เปิดคำขอ → เลือก **อนุมัติ** (เลือกทนาย 1 คน เห็นจำนวนเคสที่ทนายดูแลอยู่) หรือ **ปฏิเสธ** (ต้องระบุเหตุผล) → ยืนยัน |
| Main flow (Lawyer) | แท็บ Chat แสดง "เคสที่ได้รับมอบหมาย" → เปิดดูรายละเอียดและลูกความ → Ready to Chat |
| Alternative flow | 3a. หัวข้อหรือลำดับเหตุการณ์ว่าง → แสดงข้อความผิดพลาด<br>4a. ลูกความยกเลิกคำขอได้ระหว่างรอตรวจสอบ<br>5a. ถูกปฏิเสธ → แสดงเหตุผลจากทีมงาน + ปุ่ม "ส่งคำขอใหม่" |
| Business rules | ส่งคำขอได้เฉพาะ Client · อนุมัติ/ปฏิเสธได้เฉพาะ Admin และพิจารณาได้ครั้งเดียว · มอบหมายได้เฉพาะบัญชี Lawyer · แต่ละคนเห็นเฉพาะคำขอที่เกี่ยวข้องกับตัวเอง · บัญชี Admin สร้างจาก seed เท่านั้น |
| Postcondition | คำขอถูกบันทึกพร้อมสถานะ ผู้พิจารณา เวลา และทนายที่รับผิดชอบ → ต่อยอดเป็น UC Chat |
| UI | `docs/figma` — Chat, Chat_request, Lawyer_request (4 หน้า) |

## UC-06: Chat (extend Lawyer_request)

| Item | Description |
|---|---|
| Actor | Client และ Lawyer ของเคสนั้นเท่านั้น (Admin ไม่เห็นเนื้อหาแชท) |
| Precondition | คำขอปรึกษาได้รับอนุมัติแล้ว (มีทนายผู้ดูแล) |
| Main flow | 1. ลูกความ: แท็บ Chat → รายการ "แชทกับทนาย" (แสดงข้อความล่าสุด) → แตะเพื่อเข้าห้อง / ทนาย: เปิดเคส → Ready to Chat<br>2. พิมพ์ข้อความแล้วกดส่ง → อีกฝ่ายเห็นทันที (real-time)<br>3. กด + → "ส่งรูปภาพ" หรือ "ส่งไฟล์ PDF" → เห็นไฟล์ที่เลือกก่อนส่ง พิมพ์ข้อความประกอบได้<br>4. แตะรูปเพื่อดูเต็มจอ / แตะไฟล์ PDF เพื่ออ่านในแอปและดาวน์โหลด<br>5. เลื่อนขึ้นเพื่อโหลดข้อความเก่า |
| Extension: ปิดเคส (ยินยอมทั้งสองฝ่าย) | 1. ทนาย**หรือลูกความ**กด "ปิดเคส" + ยืนยัน → ส่ง**คำขอปิดเคส** (ยังไม่ปิด แชทยังคุยต่อได้) คนขอเห็นแถบ "รอ...ยินยอม" และยกเลิกคำขอได้<br>2. อีกฝ่ายเห็น**หน้าต่างเด้ง** (ทันทีถ้าเปิดห้องอยู่ หรือเมื่อเข้าห้อง) + แถบค้างเหนือช่องพิมพ์ + ป้ายในรายการแชท/คำขอ<br>3a. **ยินยอม** → เคสปิด ทั้งสองฝ่ายส่งข้อความไม่ได้ แต่ดูประวัติได้ (หน้าจออีกฝ่ายล็อกทันที) → ต้องการปรึกษาต่อต้องส่งคำขอใหม่<br>3b. **ไม่ยินยอม** → การปรึกษาดำเนินต่อ คนขอเห็นผลทันที<br>มีคำขอค้างได้ทีละ 1 อัน · ทุกขั้นตอนบันทึกเป็น**ข้อความระบบ**ในแชทให้ทั้งสองฝ่ายเห็น และแจ้งเตือนอีกฝ่าย |
| Alternative flow | 3a. ไฟล์ไม่ใช่รูป/PDF หรือเกิน 10 MB → แสดงข้อความผิดพลาด<br>2a. การเชื่อมต่อหลุด → เชื่อมใหม่อัตโนมัติและโหลดข้อความที่พลาดไป |
| Business rules | แชทเป็นความลับ: เฉพาะลูกความและทนายของเคส · ไฟล์แนบไม่เปิดสาธารณะ เปิดผ่านลิงก์ที่มีอายุ · ข้อความ ≤ 2,000 ตัว · แนบได้ 1 ไฟล์ต่อข้อความ |
| Postcondition | ข้อความและไฟล์ถูกบันทึกในเคส |
| UI | `docs/figma` — chat_box |

## UC-07: Notification (กระดิ่ง)

| Item | Description |
|---|---|
| Actor | Client, Lawyer, Admin (แต่ละคนเห็นเฉพาะการแจ้งเตือนของตัวเอง) |
| Precondition | ผู้ใช้ล็อกอินแล้ว |
| Main flow | 1. เมื่อมีเหตุการณ์ที่เกี่ยวกับผู้ใช้ ตัวเลขสีแดงบนกระดิ่ง (มุมขวาบนของหน้า Communication, E-Book, Message, Profile) เพิ่มขึ้นทันที<br>2. แตะกระดิ่ง → หน้า Notification แสดงรายการล่าสุด รายการที่ยังไม่อ่านเป็นพื้นสีฟ้าพร้อมจุดแดง<br>3. แตะรายการ → ไปยังเรื่องนั้น (โพสต์ / ห้องแชท / คำขอ) และนับว่าอ่านแล้ว<br>4. กด "อ่านทั้งหมด" เพื่อล้างทั้งหมด |
| เหตุการณ์ | ลูกความ/ทนาย: คอมเมนต์ใหม่ในโพสต์ของเรา, มีคนตอบกลับคอมเมนต์ของเรา, ข้อความแชทใหม่ · ลูกความ: ทนายรับเรื่องแล้ว, คำขอไม่ได้รับการอนุมัติ, ทนายขอปิดเคส/ยกเลิกคำขอ · ทนาย: ได้รับมอบหมายเคสใหม่, ลูกความยินยอม/ไม่ยินยอมปิดเคส · Admin: มีคำขอปรึกษาใหม่รอพิจารณา |
| Business rules | เรื่องเดียวกันที่ยังไม่อ่านรวมเป็นรายการเดียวพร้อมจำนวน · เปิดดูเรื่องนั้นแล้ว = อ่านแล้วอัตโนมัติ · ไม่แจ้งข้อความแชทขณะผู้รับเปิดห้องนั้นอยู่ · ไม่แจ้งเหตุการณ์ที่ผู้ใช้ทำเอง · โพสต์/คำขอถูกลบ → การแจ้งเตือนของเรื่องนั้นถูกลบด้วย · แจ้งเตือนในแอปเท่านั้น (ไม่มี push notification) |
| UI | `docs/figma` — Notification |

## UC-08: Profile & Settings

| Item | Description |
|---|---|
| Actor | Client, Lawyer, Admin |
| Precondition | ผู้ใช้ล็อกอินแล้ว |
| Main flow | 1. แท็บ Profile แสดงโปรไฟล์ของตัวเอง: แถบสี (ลูกความ = น้ำเงิน, ทนาย = เหลือง), รูป, ชื่อ, คำแนะนำตัว, Details (เบอร์/อีเมล)<br>2. ลูกความ: จำนวนโพสต์ + รายการโพสต์ของตัวเอง (รวมโพสต์ไม่ระบุตัวตน) · ทนาย: จำนวนเคสที่ดูแล + ความคิดเห็น, รายละเอียดทนาย, ความคิดเห็นล่าสุด (แตะเพื่อเปิดโพสต์)<br>3. แตะชื่อผู้เขียนโพสต์/คอมเมนต์ใน Community → เปิดโปรไฟล์ของคนนั้น |
| Extension: แก้ไขโปรไฟล์ | ไอคอนดินสอ หรือ Settings > Account → เปลี่ยน/ลบรูป (มีผลทันที), ชื่อ, นามสกุล, เบอร์โทร, คำแนะนำตัว (≤ 150) · ทนาย: รายละเอียดทนาย (≤ 1,000) และสวิตช์ "แสดงเบอร์โทรและอีเมลในโปรไฟล์" · อีเมล เลขบัตร บทบาท แก้ไม่ได้ |
| Extension: Settings | เมนู ☰ มุมซ้ายบนของทุกแท็บ → Account, Privacy and security (เปลี่ยนรหัสผ่าน ต้องกรอกรหัสเดิม), **Notifications** (เปิด/ปิด: คอมเมนต์และการตอบกลับ, ข้อความแชท (ไม่แสดงให้ admin), ความคืบหน้าของเคส — เก็บที่บัญชี ปิดแล้วไม่สร้างการแจ้งเตือนใหม่ประเภทนั้น), **Posting settings** (เฉพาะลูกความ: โพสต์แบบไม่ระบุตัวตนเป็นค่าเริ่มต้น), **Reading preferences** (จำหน้าที่อ่านค้างไว้ (เปิดเป็นค่าเริ่มต้น), หน้ากระดาษโทนมืด — เก็บในเครื่อง ใช้กับตัวอ่าน E-Book), **Dark mode** (สวิตช์เปิด/ปิด มีผลทันทีทั้งแอป จำค่าไว้ในเครื่อง), **Language** (ภาษาไทย/English — เริ่มต้นไทย มีผลทันทีทั้งแอปรวมข้อความ error และการแจ้งเตือน จำค่าไว้ในเครื่อง), Help and support (คำถามที่พบบ่อย), Log out (ยืนยันก่อน) |
| Business rules | เบอร์/อีเมล: เห็นเฉพาะเจ้าของ ยกเว้นทนายที่เปิดแสดงเอง (ลูกความซ่อนเสมอ) · โพสต์ไม่ระบุตัวตนไม่แสดงในโปรไฟล์ที่คนอื่นเห็น และไม่นับในจำนวนโพสต์ · ติดตามแบบทางเดียว ลูกความ/ทนายเท่านั้น (admin ไม่อยู่ในระบบนี้) · โพสต์ไม่ระบุตัวตนไม่แจ้งผู้ติดตามและไม่อยู่ในแท็บติดตาม · ไม่มีปุ่ม Message (แชทต้องผ่านคำขอปรึกษา) · Language ไม่แปลเนื้อหาที่ผู้ใช้เขียนและตัวบทกฎหมาย · การแจ้งเตือน/ข้อความระบบในแชทที่บันทึกก่อนมีระบบภาษายังเป็นภาษาไทย · Dark mode ไม่ตามการตั้งค่าของเครื่อง และไม่ผูกกับบัญชี (เปลี่ยนเครื่อง = ค่าเริ่มต้นสว่าง) |
| Extension: ติดตาม (Follow) | 1. เปิดโปรไฟล์ลูกความ/ทนายคนอื่น → กด "ติดตาม" (กดอีกครั้ง = เลิกติดตาม ต้องยืนยัน)<br>2. โปรไฟล์แสดง "N ผู้ติดตาม · M กำลังติดตาม" แตะเพื่อดูรายชื่อ<br>3. หน้าชุมชนมีแท็บ ทั้งหมด / ติดตาม<br>4. แจ้งเตือน: มีผู้ติดตามใหม่ (รวมเป็นรายการเดียว แตะแล้วไปรายชื่อผู้ติดตาม), คนที่ติดตามโพสต์ใหม่ — ปิดได้ที่ Settings > การแจ้งเตือน > ผู้ติดตาม |
